## 1

这里的@JsonFormat什么时候触发，要手动触发还是自动触发?

~~~java
@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")
private Date createTime;
~~~

自动触发，无需手动调用。
@JsonFormat 是 Jackson 的注解，在 Spring Boot 中由 ObjectMapper 自动处理，触发时机是两个方向：

1. 序列化（对象 → JSON）：Controller 返回对象时（如 @RestController 的返回值），Jackson 自动按 pattern 格式化 Date 为字符串。
2. 反序列化（JSON → 对象）：接收请求时（如 @RequestBody），Jackson 自动按 pattern 解析字符串为 Date。

PageHelper实现分页:

~~~java
public PageResult page(EmpQueryParam empQueryParam) {
    //1. 设置PageHelper分页参数
    PageHelper.startPage(empQueryParam.getPage(), empQueryParam.getPageSize());
    //2. 执行查询
    List<Emp> empList = empMapper.list(empQueryParam);
    //3. 封装分页结果
    Page<Emp> p = (Page<Emp>)empList;
    return new PageResult(p.getTotal(), p.getResult());
}
~~~



问题：一定要把List<Emp> empList = empMapper.list(empQueryParam);放在PageHelper.startPage(empQueryParam.getPage(), empQueryParam.getPageSize());PageHelper.startPage(empQueryParam.getPage(), empQueryParam.getPageSize());的下一行，分页才会生效吗？

* 不需要严格写在下一行，但必须是紧跟着的下一个 MyBatis 查询。
  PageHelper 的原理是：调用 startPage() 时将分页参数存入 ThreadLocal，当紧接着的下一个 MyBatis 查询执行时，PageHelper 拦截器会自动读取这些参数进行分页，然后立即清除。所以只要 startPage() 和你的目标查询之间没有其他 MyBatis 查询，分页就能生效，中间穿插普通 Java 代码（比如日志、参数校验等）完全没问题。





## 3

**为什么share-api-rule下面要新建org.springframework.boot.autoconfigure.AutoConfiguration.imports这个文件，然后里面的com.share.rule.factory.RemoteFeeRuleFallbackFactory
又是什么意思？**

* 一、为什么要建 AutoConfiguration.imports 这个文件？
  **问题根源：**包扫描扫不到
  share-api-rule 是一个公共 API jar 模块，被 share-order、share-device 等业务服务依赖（它们通过 @Autowired RemoteFeeRuleService 远程调用规则服务）。
  但这里有个矛盾：

* | 类                             | 所在包                                                 |
  | ------------------------------ | ------------------------------------------------------ |
  | `share-order` 启动类           | `com.share.order`                                      |
  | `RemoteFeeRuleFallbackFactory` | `com.share.rule.factory`（在 `share-api-rule` jar 里） |

* @SpringBootApplication 的组件扫描默认只扫启动类所在包及其子包。com.share.order 扫不到 com.share.rule.factory，所以即使 RemoteFeeRuleFallbackFactory 标了 @Component，share-order 启动时根本不会把它注册成 Bean。
  而 @FeignClient(fallbackFactory = RemoteFeeRuleFallbackFactory.class) 要求 Feign 在创建代理时能从容器中 getBean() 到这个工厂——找不到 Bean 就会启动报错。
  **解决方案：**借"自动装配"机制注册



**那com.share.rule.api里的RemoteFeeRuleService能被share-order识别到？**

| 机制             | 扫描者                  | 扫描范围                                     | 找什么                   |
| ---------------- | ----------------------- | -------------------------------------------- | ------------------------ |
| `@ComponentScan` | Spring Boot             | 仅启动类所在包 `com.share.order`             | `@Component` 等注解的类  |
| Feign 注册器     | `FeignClientsRegistrar` | `basePackages = "com.share"`（覆盖所有 jar） | 只找 `@FeignClient` 接口 |
| 自动装配         | Spring Boot             | 所有 jar 的 `AutoConfiguration.imports`      | 清单里列出的配置类       |

**一句话总结：**Feign 接口能被识别，是因为 @EnableRyFeignClients 默认扫描整个 com.share 包（包含依赖 jar 里的接口），这是一条独立于组件扫描的注册通道；而降级工厂是普通 Bean，蹭不上这条通道，只能靠自动装配文件兜底注册。






## 4

**为什么BaseEntity要继承Serializable，Serializable有什么作用吗?**

`BaseEntity` 继承 `Serializable` 是为了让它及其子类对象可以被序列化，也就是转换成字节流，以便传输或保存。

常见用途包括：

- 放入 Redis、Session 等缓存或会话存储。
- 通过 RPC、消息队列、远程调用在服务之间传输。
- 写入文件，或使用某些框架的对象复制/持久化机制。
- Java Web 分布式 Session 场景中，由容器复制 Session 数据。

`Serializable` 本身是一个标记接口，没有方法；实现它表示“允许 Java 序列化”。





**什么叫序列化?**

序列化就是把内存里的对象，转换成可以保存或传输的数据格式。

例如 Java 中：

```
User user = new User(1L, "张三");
```

`user` 只存在于当前程序的内存里。程序停止后它就没了，也不能直接通过网络发给另一个服务。

序列化后，它会变成一段字节数据，可以：

- 存进 Redis、文件或数据库
- 放进 HTTP/RPC 请求、消息队列
- 发给另一个 Java 服务

接收方再把这段数据还原为 `User` 对象，这个过程叫反序列化。

简单理解：

```
Java 对象 -> 字节/文本数据 -> 传输或存储
字节/文本数据 -> Java 对象
```

Java 的 `Serializable` 表示该类允许使用 Java 原生的“对象 <-> 字节流”转换。实际 Web 接口中更常用 JSON，例如：

```
{"id":1,"name":"张三"}
```

JSON 转换也是广义上的序列化，但不依赖 Java 的 `Serializable`。





**什么场景是一定需要Serializable的？**

只有当对象要走“Java 原生序列化协议”时，才一定要实现 `Serializable`。

判断标准很简单：代码或框架是否最终使用了 `ObjectOutputStream.writeObject(...)`、`ObjectInputStream.readObject(...)`，或基于它们的序列化器。是的话，该对象及其所有非 `transient` 字段对象通常都必须可序列化。

典型场景：

- 使用 JDK 序列化器把对象存入 Redis、缓存或文件。
- Java RMI 的远程方法参数和返回值。
- 分布式/持久化 `HttpSession`，且 Servlet 容器采用 JDK 序列化复制 Session。
- 某些旧式消息、任务调度或框架明确要求对象可序列化。
- 直接写 Java 对象流：

```
try (ObjectOutputStream out =
         new ObjectOutputStream(new FileOutputStream("user.bin"))) {
    out.writeObject(user); // User 必须实现 Serializable
}
```

而这些场景不需要它：

- Spring MVC 返回 JSON。
- 接收 JSON 请求体。
- MyBatis/JPA 读写数据库实体。
- Redis 使用 JSON 序列化器，或只存字符串、数字、JSON 文本。
- HTTP、Kafka、MQTT 等使用 JSON、Protobuf、Avro 等消息格式。

因此，`Serializable` 不表示“这个对象能存储或传输”，而是表示“这个对象允许被 Java 自己的二进制序列化机制处理”。现代服务端项目通常更倾向 JSON、Protobuf 等显式格式；保留 `Serializable` 多半是为了框架兼容或给缓存、Session 等场景留余地。


**为什么提示无法从 static 上下文引用非 static 方法?**



**总结**

* 左边声明泛型 + 钻石语法在直接赋值时够用；一旦链式调用，建议显式写右侧类型参数。这是 Java 8~17 类型推断的普遍现象。

  ~~~java
  // 写法1：分两步，避免链式调用干扰类型推断
  LambdaQueryWrapper<Cabinet> coutWrapper = new LambdaQueryWrapper<>();
  coutWrapper.eq(Cabinet::getCabinetNo, cabinet.getCabinetNo());
  
  // 写法2：Wrappers 工具方法（推荐，最简洁）
  LambdaQueryWrapper<Cabinet> coutWrapper = new LambdaQueryWrapper<Cabinet>()
                  .eq(Cabinet::getCabinetNo,cabinet.getCabinetNo());
  long count = count(coutWrapper);
  ~~~
